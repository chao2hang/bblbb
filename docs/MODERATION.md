# BBLBB — 审核、举报与处罚

> 版本：v0.4
> 审核是不可停用的核心模块。所有动作保留原因、操作者、前后状态和审计关联。

## 1. 目标

- 为用户提供明确、可追踪的举报入口。
- 让版主在自己的板块范围内安全工作。
- 处罚具有范围、期限、理由、撤销和申诉。
- 内容操作可恢复并保留 revision。
- 避免管理员直接改数据库导致无审计状态漂移。

## 2. 举报

可举报：帖子、回复、用户资料和附件。

原因码示例：

- `spam`
- `harassment`
- `illegal_content`
- `privacy`
- `copyright`
- `malware`
- `wrong_board`
- `other`

规则：

- 举报详情限长，不接受 HTML。
- 同用户对同目标和同原因的开放举报去重。
- 被举报者看不到举报者身份和内部备注。
- 恶意举报可被单独处罚，但不能阻止用户申诉。
- 严重原因可自动提升优先级，但不能自动定罪。

状态：

```text
open → triaged → resolved
  └────────────→ rejected
open ──────────→ withdrawn（仅举报者在未处理前）
```

## 3. 审核案件

多个举报可合并为一个 `moderation_case`。

状态：

```text
open → in_review → resolved → closed
  └──────────────→ closed（无措施）
```

- 案件有优先级、负责人和内部备注。
- 版主只能领取其板块范围内案件。
- 跨板块/用户全局案件需要全局审核权限。
- 处理动作与案件状态变更分开记录，避免“resolved”掩盖实际做了什么。

## 4. 内容状态与操作

帖子/回复允许：

- `hide`：普通用户不可见，作者可看到状态和申诉入口。
- `restore`：恢复到上一个合法状态。
- `delete`：软删除；保留 revision 和审计。
- `move`：移动主题到另一板块，重新校验标签/权限。
- `lock/unlock`：关闭/恢复回复。
- `pin/unpin`、`feature/unfeature`。
- `merge`：合并主题，旧 URL 保留重定向和记录。
- `edit_for_moderation`：移除敏感内容，必须保存前版本和原因。

版主操作他人内容必须提供非空理由。

## 5. 处罚

### 类型

| 类型 | 效果 |
|---|---|
| `warning` | 记录警告并通知，无直接权限变化 |
| `rate_limit` | 降低发帖/回复速率 |
| `mute` | 全站禁止发帖和回复 |
| `board_mute` | 指定板块禁止写入 |
| `ban` | 禁止登录，撤销 Session/OAuth Refresh Token |

- 每项处罚有开始、结束、原因、证据关联和创建者。
- 永久处罚 `ends_at` 为空。
- 撤销不删除原处罚，而是填写撤销人、时间和理由。
- 到期判断在请求时实时计算；worker 负责通知和归档，不作为正确性的唯一来源。
- 处罚不得阻止用户获取自己的数据或提交合法申诉。

## 6. 申诉

状态：

```text
submitted → in_review → accepted/rejected
```

- 原处罚执行者不得作为唯一复核人；小型站点至少在 UI 显示利益冲突提醒。
- 接受申诉会创建撤销/补偿动作，而不是删除历史。
- 申诉内容对审核员可见，不对普通用户公开。
- 限制重复申诉和骚扰，但保留紧急联络方式。

## 7. 自动审核

v1 可提供：

- 新用户前 N 帖进入 `pending`。
- 链接数量、重复内容、敏感词和频率规则打分。
- Turnstile 验证。
- 命中规则进入队列或临时折叠，不自动永久封禁。

所有自动动作记录：规则版本、分数、输入摘要和最终结果。敏感词命中日志不得复制完整私密/隐藏正文。

## 8. 权限范围

- 板块 moderator：处理本板块内容、举报和板块处罚。
- 全局 moderator：跨板块内容和一般用户案件。
- administrator：角色、系统设置、永久封禁和高风险动作。
- `moderation.review` 与 `moderation.sanction` 分开，可让部分审核员只分类不处罚。
- 版主不能处理自己的举报/被举报案件；必要时升级给其他管理员。

## 9. 审计与通知

每个动作写：

- actor、target、case、request ID。
- before/after 状态摘要。
- reason、outcome、时间和作用域。
- 必要时关联 revision、sanction 或 point compensation。

通知：

- 举报受理结果可向举报者显示有限信息。
- 被处理用户收到动作类型、公开原因、期限和申诉入口。
- 内部证据、举报人和风控细节不得泄漏。

## 10. 管理后台

至少提供：

- 按优先级、板块、类型、状态、负责人过滤队列。
- 批量分类，但处罚和删除仍逐项确认或提供批量原因。
- 用户处罚时间线。
- 内容 revision 对比。
- 同目标重复举报合并提示。
- 权限范围提示和越权拒绝。
- 审计日志跳转。

## 11. 数据保留

- 删除内容的 revision 保留时间可配置，并满足法律/隐私要求。
- 举报人身份严格最小权限访问。
- 案件关闭后内部备注按策略保留。
- 用户注销时，必要审核记录匿名化而非破坏案件链路。
- 法律保留和普通站点删除策略分开配置。

## 12. 测试与验收

- 每个状态迁移测试合法与非法路径。
- 板块版主不能处理其他板块。
- 审核员不能处理自己的案件。
- 处罚到期即时恢复权限，无需等 worker。
- 恢复内容能回到正确版本。
- 封禁撤销 Session 和 Refresh Token。
- 未授权用户无法通过 ID 枚举读取举报人、备注和 revision。
- 批量操作部分失败时有明确逐项结果，不伪装全部成功。
